# Cross-Boundary Assurance experimental profile 0.1

This is a non-normative research profile, not a ratified standard. The reference implementation is `ddcar.cba`. Its only decision outputs are CONSISTENT and DIVERGENT, with `authorization: NOT_EVALUATED` and `mode: shadow`. Neither output permits execution.

The eight boundaries are identity, authority, representation, policy, state, execution, observation, and evidence. The caller supplies an explicit policy identifying critical top-level commitment fields, required boundaries, optional text fields, and an optional maximum logical inter-event age. Critical fields are compared by deterministic JSON digest, without normalization or coercion. A separately supplied baseline is compared to the commitment itself before event processing. Missing fields, untrusted observations, replay within the trace, reordering, and configured temporal gaps are reported. Text indicators include non-NFC, compatibility normalization, invisible formatting, and bidi controls. They are not comprehensive Unicode security validation.

The input and report digest algorithm is SHA-256 over UTF-8 JSON with sorted keys, compact separators, and non-ASCII preservation. This is an internal research encoding, not DDCAR-CJ1 or a portable signed wire protocol. No signature, trust anchor, clock, or external state is established by this profile. Production consumers MUST NOT interpret a positive diagnostic as authorization, and MUST NOT weaken or replace existing DDCAR verification or executor gates. See `docs/CBA-RESEARCH.md` for limitations and release gates.
